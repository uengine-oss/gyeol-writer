# 결 워드 (Gyeol Writer)

HWPX·HWP 문서를 열고 편집해 HWPX로 저장하는 데스크톱 워드프로세서. Electron + TypeScript + ProseMirror.

![결 워드에서 연구개발계획서 양식(HWPX)을 연 화면](docs/screenshot.png)

**[내려받기 (macOS · Windows)](https://github.com/uengine-oss/gyeol-writer/releases/latest)**

## AI 도우미 (0.3)

오른쪽 **AI 도우미** 창에서 이 컴퓨터에 설치된 [Claude Code](https://claude.com/claude-code)(`claude`) 또는 [Codex](https://github.com/openai/codex)(`codex`)를 불러 문서를 함께 쓴다. 따로 API 키를 넣지 않고, 각 에이전트에 로그인한 계정을 그대로 쓴다.

![AI 도우미가 선택한 막대 그래프를 고친 화면](docs/ai-agent.png)

▶ **[시연 영상 (2분, 한국어 나레이션)](https://github.com/uengine-oss/gyeol-writer/releases/download/v0.3.0/gyeol-writer-ai-agent.mp4)**

| 작업 | 대상 | 하는 일 |
|---|---|---|
| 본문에 쓰기 | 커서 자리 | 문서 앞뒤 흐름을 읽고 문단·제목·목록·표를 써 넣는다 |
| 선택 부분 고치기 | 선택한 글자 | 선택한 부분만 고쳐 그 자리에 바꿔 넣는다(문체 다듬기, 개조식, 맞춤법, 번역 등) |
| 그림 고치기 | 선택한 그림 | 에이전트가 Python(PIL)·SVG·이미지 생성 도구로 그림을 고쳐 같은 자리에 바꿔 넣는다 |
| 그림 그리기 | 커서 자리 | 도식·일러스트를 그려 넣는다(Claude는 SVG, Codex는 이미지 생성 또는 SVG) |
| 묻기 | 문서 전체 | 본문은 그대로 두고 답한다. 답을 '본문에 넣기'로 옮길 수 있다 |

- 선택에 따라 작업 종류가 자동으로 바뀐다(그림 선택 → 그림 고치기, 글자 선택 → 고치기, 선택 없음 → 쓰기).
- 에이전트가 일하는 동안 본문의 대상 자리에 표시가 붙고, 그 사이 편집을 해도 결과는 원래 자리를 따라가 들어간다.
- 결과는 되돌리기 한 번(⌘Z 또는 '되돌리기' 단추)으로 되돌린다. 넣은 표·그림은 HWPX로 그대로 저장된다.
- 글 작업은 도구 없이 바로 답하게 하고(빠르다), 그림 작업만 임시 작업 폴더 안에서 파일 쓰기·Python 실행을 허용한다. Codex는 읽기 전용(글) / 작업 폴더 쓰기(그림) 샌드박스로 실행한다.
- 앱으로 실행하면 터미널 PATH를 물려받지 못하므로 로그인 셸에서 PATH를 얻어 `claude`·`codex`를 찾는다. 설치 뒤에는 창의 ↻ 로 다시 찾는다.

## 만든 방식 — 클린룸

한컴오피스 한글(Mac 12.30)을 **코드를 열지 않고** 관찰해 기능 명세를 만들고, 공개 형식 문서를 기준으로 새로 구현했다.

| 단계 | 한 일 | 하지 않은 일 |
|---|---|---|
| 관찰 | REA(`inspect-plist`, `decode-interface-builder`)로 번들 메타데이터·지원 형식·대화상자 nib 64개 목록, 도움말 폴더 구조(기능 분류 87항목)를 확인 | 실행 파일·프레임워크 디스어셈블/디컴파일 |
| 형식 | HWPX(OWPML, KS X 6101)·HWP 5.0 공개 형식 문서 + 실제 문서 파일(데이터)의 구조 분석 | 한컴 코드·타 오픈소스 HWP 라이브러리 코드 참조 |
| 구현 | 명세만 보고 새로 작성. 아이콘·로고·UI 디자인 모두 자체 제작 | 한컴 아이콘·이미지·서식 파일 복사 |

한컴 사용권 계약은 역분석을 금지하고, 저작권법 제101조의4의 역분석 허용은 호환 정보를 달리 얻을 수 없을 때에 한정된다. HWP 형식은 공개되어 있으므로 바이너리 분석 없이 진행했다.

## 기능

- **파일**: HWPX 열기·저장, 문서 파일을 창에 끌어 놓아 열기, HWP 5.0(바이너리) 열기 → HWPX로 저장, HWTX(서식 파일)로 새 문서, TXT 열기, PDF로 저장, 인쇄, 문서 정보(제목·지은이·통계), 저장 안 한 변경 확인, 최근 문서, Finder에서 열기
- **글자**: 글꼴(시스템 글꼴 목록), 크기, 진하게·기울임·밑줄·취소선·위/아래 첨자, 글자 색, 형광펜(음영), 장평·자간 — 글자 모양 대화상자(미리 보기)
- **문단**: 양쪽·왼쪽·가운데·오른쪽·배분 정렬, 왼쪽/오른쪽 여백, 들여쓰기/내어쓰기, 줄 간격(%), 문단 위/아래 간격 — 문단 모양 대화상자, 스타일(바탕글·본문·개요 1~3)
- **쪽**: 편집 용지(A4·A3·A5·B4·B5·Letter·Legal·사용자 정의, 세로/가로, 여백 7종, 미리 보기), 쪽 단위 화면, 쪽 나누기(⌘Enter)
- **입력**: 표 만들기(격자 선택), 그림(파일·붙여넣기·끌어 놓기), 그림 자르기(두 번 누르기), 탭, 줄 바꾸기, 날짜, 특수 문자
- **AI 도우미**: 본문 쓰기·선택 부분 고치기·그림 고치기·그림 그리기·묻기 (설치된 Claude Code / Codex, ⌘J)
- **표**: 줄/칸 추가·삭제, 셀 합치기·나누기, 셀 배경색, 테두리 보이기/숨기기, 열 너비 끌기, Tab으로 칸 이동
- **편집**: 되돌리기/다시 실행, 찾기·찾아 바꾸기(모두 바꾸기, 대소문자), 조판 부호 보이기, 확대/축소(30~300%, 쪽 맞춤), 상태 표시줄(쪽·글자 수·수정 여부)

## 설치

[Releases](https://github.com/uengine-oss/gyeol-writer/releases) 에서 받거나 직접 만든다(`npm run dist` → `release/`).

| 운영체제 | 파일 | 처음 실행 |
|---|---|---|
| macOS (Apple Silicon) | `GyeolWriter-<버전>-mac-arm64.dmg` | 개발자 인증서 없이 임시 서명했으므로 처음 한 번은 앱을 우클릭 → 열기 |
| macOS (Intel) | `GyeolWriter-<버전>-mac-x64.dmg` | 위와 같음 |
| Windows 10/11 (x64) | `GyeolWriter-<버전>-win-x64-setup.exe` | 코드 서명이 없어 SmartScreen 경고가 뜨면 '추가 정보 → 실행' |

설치하면 `.hwpx`·`.hwp`·`.hwtx` 파일을 결 워드로 열 수 있다.

## 개발

```bash
npm install
npm run dev        # 개발 실행
npm run build && npm start
npm run dist       # release/ 에 맥 DMG(arm64·x64)와 윈도우 설치 파일(x64)
npm run dist:mac   # 맥만 / npm run dist:win  윈도우만(맥에서 교차 빌드 가능)
npm test           # 형식 단위 테스트
GYEOL_HWPX_SAMPLES=/폴더 GYEOL_HWP5_SAMPLES=/폴더 npx vitest run src   # 실제 문서로 왕복 시험
```

VS Code 등 Electron 기반 터미널에서 실행하면 `ELECTRON_RUN_AS_NODE=1` 이 물려 있어 앱이 뜨지 않는다. `env -u ELECTRON_RUN_AS_NODE npm run dev` 로 실행한다.

## 구조

```
src/model/doc.ts          형식과 무관한 문서 모델 (단위 HWPUNIT = 1/7200 inch)
src/format/hwpx/          HWPX 읽기·쓰기 (header.xml 참조 테이블 중복 제거, BinData)
src/format/hwp5/          HWP 5.0 읽기 (OLE 복합 파일, raw deflate, 레코드 트리)
src/editor/               ProseMirror 스키마·변환·명령·쪽 배치·찾기, 마크다운 ↔ 문서(markdown.ts), AI 작업 자리 표시(aitarget.ts)
src/renderer/src/         화면(도구 상자, 서식 도구 모음, 대화상자, 상태 표시줄, AI 도우미 창 agent.ts)
src/main/                 Electron 메인(메뉴, 파일 대화상자, PDF·인쇄), agent.ts: claude·codex 찾기·실행·결과 수집
scripts/                  호환성·AI 도우미 시연 샘플 생성, 파일 내용 요약
samples/                  결 워드가 만든 HWPX (한글 호환성 확인용)
```

검증용 실행 옵션(메인 프로세스): `GYEOL_OPEN=파일`, `GYEOL_CAPTURE=out.png`(화면 저장 후 종료), `GYEOL_CAPTURE_PDF=out.pdf`, `GYEOL_E2E_STEPS=steps.json`(실제 입력 이벤트로 편집: insert/key/menu/js), `GYEOL_E2E_OUT=out.hwpx`.

## 형식 구현 메모

- 문단 여백은 `hp:switch` 안에 두 벌 저장된다. HwpUnitChar `case` 값이 실제 값이고 `default` 값은 2배다(실물 문서 확인). 읽을 때 case, 쓸 때 두 벌 모두 기록.
- HWP에서 변환된 HWPX는 취소선 없음을 `strikeout shape="3D"` 로 저장한다(실물 문서 740건). `NONE`·`3D` 모두 취소선 아님으로 처리.
- `landscape="WIDELY"` 가 세로(기본) 방향이다.
- 이미 압축된 그림(png/jpg/gif/webp)은 ZIP 안에서 다시 압축하지 않는다(80MB 문서 저장 6초 → 1초 미만).
- 줄 배치 캐시(`hp:linesegarray`)는 쓰지 않는다 — 한글이 열 때 다시 계산한다고 가정. **한글에서 열어 확인 필요.**

## 한글과의 배치 일치

한글이 HWPX 안에 저장한 배치 캐시(줄의 쪽 안 위치 `vertpos`, 줄 시작 글자 `textpos`, 칸 높이 `cellSz`)와 1쪽 미리보기 그림을 정답으로 삼아 비교·보정했다.

- 쪽 나눔: 표는 줄 단위로, 쪽보다 큰 줄은 칸 안 문단의 줄 단위로 나눈다. 구역마다 새 쪽.
- 줄 간격은 줄 아래에 붙고 칸의 마지막 줄 뒤는 버린다. 줄이 쪽에 들어가는지는 글자 높이로 판단한다.
- 칸 안쪽 여백은 표의 `inMargin`(칸의 `hasMargin="1"` 이면 칸 값), 글자처럼 취급한 표의 아래 간격은 `(줄 간격-100)% × 글자 크기`.
- 한글 글꼴이 없는 환경의 줄바꿈 보정(`src/editor/fontfit.ts`): 빈칸 0.5em, 글꼴별 자간 — 실제 문서 26개 5,146문단에서 한글과 같은 위치에서 줄이 바뀌는 비율 74% → 79%.
- 시험 문서(연구개발계획서 10구역): 한글 23쪽 / 결 워드 27쪽, 10구역 중 7구역 쪽 수 일치. 남은 차이는 대체 글꼴 폭.

## 한계 (MVP)

- 화면은 첫 구역의 용지 크기로 그린다(구역별 용지 설정은 저장 시 보존).
- 한 줄(행)짜리 문단이 한 쪽보다 길면 나누지 않는다.
- 머리말/꼬리말, 각주/미주, 쪽 번호 넣기, 수식, 차트, 글맵시, 다단, 문단 번호/글머리표 모양, 탭 위치 설정, 변경 추적, 메모는 아직 없다(열 때 건너뜀, 본문 텍스트는 보존).
- 한글 글꼴(휴먼명조·한양중고딕 등)이 없으면 대체 글꼴을 써서 줄바꿈이 일부 다를 수 있다.
- 글상자 안 문단은 본문 흐름으로 펼친다. 그림은 글자처럼 취급(본문 배치)만 지원.
- 셀 테두리는 표 전체 단위(전부 실선/없음). 개별 선 종류·굵기는 보존하지 않는다.
- HWP(바이너리) 저장, DOCX/ODT 입출력, 맞춤법 검사, 한자 변환은 없다.
- 맥(arm64·Rosetta x64)에서 시험했다. 윈도우 설치 파일은 만들었으나 실제 윈도우에서는 아직 시험하지 않았다.
